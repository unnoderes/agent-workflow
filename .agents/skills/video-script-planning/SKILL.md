# video-script-planning

## 1. 搜索素材

使用 `web_search` 至少搜索 3 次，覆盖主题核心信息、行业案例、用户痛点。每次搜索记录可用的钩子（引人注意的开场点）、数据、对比点。

完成标准：有足够信息支撑 5 段以上的脚本内容。

## 2. 设计结构

基于搜索结果，设计视频段落结构：

- 开场（5-10%）：钩子，提出问题或冲突
- 主体-问题展开（20-30%）：痛点共鸣
- 主体-解决方案（40-50%）：核心内容
- 主体-案例/对比（10-20%）：具体化验证
- 结尾（5-10%）：总结 + CTA

快节奏短视频（抖音/Reels）压缩至 3-5 段。教育类增加原理段，营销类增加社会证明段。

输出结构方案（段落标题 + 时长），等待用户确认。用户无回应或同意则继续。

完成标准：结构明确，每段有时长和目标。

## 3. 写分段脚本

为每段生成：

**文案**：口语化短句，适合 TTS。前 3 秒必须有钩子（疑问/数据/反差）。每段 5-20 秒。

**视觉**：画面主体（标题卡/数据展示/对比图/代码片段/真实截图）+ 标注「Claude 生成 HTML」或「用户手动截图」。参考判断标准：
- 标题卡、特性亮点、数据、代码片段 → Claude 生成
- 真实 UI、运行效果、第三方 Logo → 用户截图

**关键词**：2-4 个核心概念。

**节奏**：快/中/慢。

完成标准：每段都有文案、视觉、关键词、节奏，且视觉标注明确。

## 4. 推荐参数

根据主题和风格，推荐：

**画面比例**：9:16（抖音/Reels）/ 16:9（B站/YouTube）/ 1:1（小红书）+ 理由。

**美术风格**：从 `agents.md` 的 5 种风格中选一种 + 理由。自定义风格需说明色调和字体。

**TTS 配置**：音色（如 `Chinese_deep_voiced_male_vv1`）+ 语速（1.0-1.4）+ 理由。

完成标准：三类参数都有推荐和理由。

## 5. 输出文档

生成 `script-plan.md`（或用户指定路径），包含：

```markdown
# [视频主题] - 内容策划方案

## 元数据
- 主题：[主题]
- 风格：[风格]
- 目标时长：[时长]
- 生成日期：[日期]

## 内容结构
[第 2 步的结构方案]

## 分段脚本
### 第1段（[角色]，[时长]）
**文案**：[文案内容]
**视觉**：[画面描述]（[Claude 生成 HTML / 用户手动截图]）
**关键词**：[关键词]
**节奏**：[快/中/慢]

[重复每段]

## 制作参数建议
### 画面规格
- 推荐比例：[比例] + [理由]

### 美术风格
- 推荐风格：[风格] + [理由]

### TTS 配置
- 推荐音色：[音色] + [理由]
- 推荐语速：[语速] + [理由]

## 素材来源
- [搜索来源1]
- [搜索来源2]
...

## 下一步
1. 运行 `init-video-project` 初始化项目目录
2. 将本方案传递给 `short-video-frames` 生成画面
3. 并行运行 `short-video-cover` 和 `tts-video`
4. 使用 `html-image-export` 导出 PNG
5. 使用 `assemble-video` 合成最终视频
```

输出文件路径后，汇报：
- 脚本段数和总时长
- 参数建议摘要
- 下一步行动

完成标准：文件已写入，包含所有必需章节。

## 规则

- **必须搜索**：第 1 步不能跳过，即使用户没有明确要求联网。
- **视觉标注强制**：第 3 步的每段视觉描述必须标注「Claude 生成 HTML」或「用户手动截图」。
- **参数必须有理由**：第 4 步的推荐不能随意，理由必须基于主题和风格。
- **不做的事**：不生成 HTML 文件，不调用 TTS API，不导出图片，不合成视频（这些由后续 skills 完成）。
