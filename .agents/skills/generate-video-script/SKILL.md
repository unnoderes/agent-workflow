# generate-video-script

## 职责

从 Notion 素材库读取内容，生成完整的视频脚本并写回 Notion。

---

## 工作流

### Phase 1 — 读取素材库

**步骤 1.1**：确认工作区 URL

用户必须提供 Notion 工作区主页面 URL（由 `collect-video-materials` 生成）。

如果用户未提供，询问：
```
请提供 Notion 工作区 URL（由 collect-video-materials 创建的工作区主页面）
```

**步骤 1.2**：提取工作区页面 ID

从 URL 中提取 page_id（Notion URL 格式：`https://notion.so/xxx-<page_id>`）。

**步骤 1.3**：获取工作区主页面内容

调用 `notion__notion_fetch__ce83b000`：

```json
{
  "url": "<工作区主页面 URL>"
}
```

从返回内容中找到「📚 素材库」子页面的 URL 或 ID。

**步骤 1.4**：读取素材库内容

调用 `notion__notion_fetch__ce83b000`：

```json
{
  "url": "<素材库页面 URL 或 ID>"
}
```

提取所有素材内容为结构化数据：
- 钩子素材列表
- 数据素材列表
- 案例素材列表
- 对比素材列表
- 参考链接列表

**完成标准**：
- 素材库内容已完整读取
- 提取到的素材按类型分类存储

---

### Phase 2 — 分析覆盖度并补充搜索（可选）

**步骤 2.1**：分析素材覆盖度

基于读取的素材，评估以下维度：

```markdown
## 素材覆盖度分析

✅ **钩子素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否包含数据型/疑问型/反差型钩子]

✅ **数据素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否有具体数值和来源]

✅ **案例素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否有真实场景和效果]

✅ **对比素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否有明确维度和结论]

---

**总体评估**: [完全充分 / 需少量补充 / 需大量补充]
```

**步骤 2.2**：决定是否补充搜索

根据覆盖度决策：

| 总体评估 | 补充搜索次数 | 搜索方向 |
|---------|------------|----------|
| 完全充分 | 0 次 | 无需补充 |
| 需少量补充 | 1 次 | 仅补充缺失项（如缺案例则搜案例） |
| 需大量补充 | 2-3 次 | 全面补充缺失维度 |

**步骤 2.3**：执行补充搜索（如需要）

使用 `web_search` 针对性搜索缺失内容，搜索后将新素材添加到内存中的素材列表（不立即写回 Notion）。

**完成标准**：
- 已评估素材覆盖度
- 已执行必要的补充搜索
- 原有素材 + 补充素材形成完整素材集

---

### Phase 3 — 设计视频结构

**步骤 3.1**：确定视频时长

询问用户或根据主题推断：
- 快节奏短视频（抖音/Reels）：30-60 秒
- 教育类（B站/YouTube）：60-120 秒
- 深度解说（B站）：120-180 秒

**步骤 3.2**：设计段落结构

基于素材和时长，设计结构：

**通用结构模板**：
```markdown
1. 开场（5-10%）：钩子，提出问题或冲突
2. 问题展开（20-30%）：痛点共鸣
3. 解决方案（40-50%）：核心内容
4. 案例验证（10-20%）：具体化验证
5. 结尾（5-10%）：总结 + CTA
```

**快节奏优化**（30-60 秒）：
```markdown
1. 开场（10%）：强钩子
2. 核心内容（70%）：解决方案 + 数据
3. 结尾（20%）：案例 + CTA
```

**教育类扩展**（60-120 秒）：
```markdown
1. 开场（5%）：钩子
2. 问题（15%）：痛点
3. 原理（30%）：核心概念
4. 实践（30%）：具体方案
5. 案例（15%）：验证
6. 总结（5%）：CTA
```

输出结构方案，等待用户确认。用户无回应或同意则继续。

**完成标准**：
- 结构明确，每段有时长和目标
- 段落数量合理（3-7 段）

---

### Phase 4 — 生成分段脚本

**步骤 4.1**：为每段生成内容

每段包含 4 个要素：

**1. 文案**
- 口语化短句，适合 TTS
- 前 3 秒必须有钩子（疑问/数据/反差）
- 每段 5-20 秒
- 示例：
  ```
  「你知道吗？90% 的开发者都在用错这个功能。今天教你正确姿势。」
  ```

**2. 视觉**
- 画面主体描述 + 视觉元素
- 标注「Claude 生成 HTML」或「用户手动截图」
- 判断标准：
  - 标题卡、特性亮点、数据、代码片段 → Claude 生成
  - 真实 UI、运行效果、第三方 Logo → 用户截图
- 示例：
  ```
  [Claude 生成 HTML]
  标题卡 + 大数字 "90%" + 问号动画
  深色背景，冷色高亮
  ```

**3. 关键词**
- 2-4 个核心概念
- 用于后续 SEO 和标签
- 示例：`错误、90%、开发者、正确姿势`

**4. 节奏**
- 快/中/慢
- 决定画面停留时间和配音语速
- 示例：`快`（开场）、`中`（主体）、`慢`（结尾强调）

**步骤 4.2**：素材引用

生成脚本时，从素材库中选择合适的素材：
- 开场段：优先使用「钩子素材」
- 问题段：优先使用「痛点素材」或「对比素材」
- 方案段：使用「核心概念」
- 案例段：优先使用「案例素材」和「数据素材」

**完成标准**：
- 每段都有完整的 4 个要素
- 视觉标注明确（Claude 生成 vs 用户截图）
- 素材引用合理

### Phase 5 — 推荐制作参数

**步骤 5.1**：推荐画面比例

根据主题和目标平台推荐：

| 比例 | 尺寸 | 适用平台 | 推荐场景 |
|------|------|---------|----------|
| 9:16 | 1080×1920 | 抖音/小红书 Reels | 移动端竖屏，快节奏内容 |
| 16:9 | 1920×1080 | B站/YouTube | 桌面端横屏，深度内容 |
| 1:1 | 1080×1080 | 小红书图文 | 社交平台分享 |

给出推荐 + 理由。

**步骤 5.2**：推荐美术风格

从 5 种风格中选择（参考 `agents.md`）：

| 风格代号 | 名称 | 特点 | 适用主题 |
|---------|------|------|----------|
| 1 | 极简白底 | 深色无衬线字，细线分隔 | 商业、产品、简洁教程 |
| 2 | 暗色技术感 | 深灰/黑底，代码字体 | 编程、技术、开发工具 |
| 3 | 暖调书卷 | 米白底，衬线标题 | 人文、设计、创意 |
| 4 | 杂志对比 | 粗重标题，强版式 | 营销、品牌、对比测评 |
| 5 | 自定义 | 用户描述 | 特殊需求 |

给出推荐 + 理由。

**步骤 5.3**：推荐 TTS 配置

根据视频风格推荐：

**音色推荐**：
| 音色 ID | 描述 | 适用场景 |
|--------|------|----------|
| `Chinese_deep_voiced_male_vv1` | 浑厚男声 | 技术解说、深度教程 |
| `Chinese (Mandarin)_Radio_Host` | 电台男主播 | 新闻式播报、资讯 |
| `Chinese (Mandarin)_Reliable_Executive` | 沉稳高管 | 商业内容、正式场合 |
| `male-qn-jingying` | 精英青年 | 年轻化内容、活力风格 |

**语速推荐**：
- 快节奏（抖音）：1.3-1.5
- 正常节奏（B站）：1.1-1.3
- 慢节奏（深度）：0.9-1.1

给出推荐 + 理由。

**完成标准**：
- 三类参数都有推荐和理由
- 推荐基于主题和素材特点，而非随意

## 规则

- **职责边界**：本 skill 只负责脚本生成，不执行视频制作（HTML 生成、TTS、导出、合成）
- **素材优先**：优先使用素材库中的内容，仅在覆盖度不足时补充搜索
- **搜索限制**：补充搜索不超过 3 次，避免重复前一阶段的工作
- **参数理由**：所有推荐参数必须有基于主题和素材的理由，不能随意
- **视觉标注强制**：每段的视觉描述必须标注「Claude 生成 HTML」或「用户手动截图」
- **Notion 优先**：优先写回 Notion，不生成本地文件（除非用户明确要求）
- **Markdown 规范**：使用 Notion-flavored Markdown，日期用 `<date>` 标签
- **错误处理**：如果无法读取素材库，报错并检查工作区 URL 是否正确

---

## 注意事项

- 必须先读取素材库内容，才能开始生成脚本
- 脚本段数应根据视频时长和内容复杂度灵活调整（3-7 段）
- 每段的文案长度要匹配标注的时长（5-20 秒）
- 开场段的钩子是成败关键，必须强有力
- 视觉描述要具体，便于后续 `short-video-frames` skill 理解
- 参数推荐要考虑目标平台和受众特点
- 工作区主页面的状态字段用于跟踪进度，后续 skills 可能依赖此字段
