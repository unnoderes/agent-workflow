# generate-video-script

## 职责

从 Notion 素材库读取内容，生成完整的视频脚本并写回 Notion。

---

## 工作流

### Phase 1 — 读取素材库

**步骤 1.1**：确认工作区 URL

用户必须提供 Notion 工作区主页面 URL（由 `collect-video-materials` 生成）。

如果用户未提供，询问：
```
请提供 Notion 工作区 URL（由 collect-video-materials 创建的工作区主页面）
```

**步骤 1.2**：提取工作区页面 ID

从 URL 中提取 page_id（Notion URL 格式：`https://notion.so/xxx-<page_id>`）。

**步骤 1.3**：获取工作区主页面内容

调用 `notion__notion_fetch__ce83b000`：

```json
{
  "url": "<工作区主页面 URL>"
}
```

从返回内容中找到「📚 素材库」子页面的 URL 或 ID。

**步骤 1.4**：读取素材库内容

调用 `notion__notion_fetch__ce83b000`：

```json
{
  "url": "<素材库页面 URL 或 ID>"
}
```

提取所有素材内容为结构化数据：
- 钩子素材列表
- 数据素材列表
- 案例素材列表
- 对比素材列表
- 参考链接列表

**完成标准**：
- 素材库内容已完整读取
- 提取到的素材按类型分类存储

---

### Phase 2 — 分析覆盖度并补充搜索（可选）

**步骤 2.1**：分析素材覆盖度

基于读取的素材，评估以下维度：

```markdown
## 素材覆盖度分析

✅ **钩子素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否包含数据型/疑问型/反差型钩子]

✅ **数据素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否有具体数值和来源]

✅ **案例素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否有真实场景和效果]

✅ **对比素材**: [充分 / 部分 / 不足]
   - 已有: X 个
   - 质量: [是否有明确维度和结论]

---

**总体评估**: [完全充分 / 需少量补充 / 需大量补充]
```

**步骤 2.2**：决定是否补充搜索

根据覆盖度决策：

| 总体评估 | 补充搜索次数 | 搜索方向 |
|---------|------------|----------|
| 完全充分 | 0 次 | 无需补充 |
| 需少量补充 | 1 次 | 仅补充缺失项（如缺案例则搜案例） |
| 需大量补充 | 2-3 次 | 全面补充缺失维度 |

**步骤 2.3**：执行补充搜索（如需要）

使用 `web_search` 针对性搜索缺失内容，搜索后将新素材添加到内存中的素材列表（不立即写回 Notion）。

**完成标准**：
- 已评估素材覆盖度
- 已执行必要的补充搜索
- 原有素材 + 补充素材形成完整素材集

### Phase 3 — 设计视频结构

**步骤 3.1**：确定视频时长

询问用户或根据主题推断：
- 快节奏短视频（抖音/Reels）：30-60 秒
- 教育类（B站/YouTube）：60-120 秒
- 深度解说（B站）：120-180 秒

**步骤 3.2**：设计段落结构

基于素材和时长，设计结构：

**通用结构模板**：
```markdown
1. 开场（5-10%）：钩子，提出问题或冲突
2. 问题展开（20-30%）：痛点共鸣
3. 解决方案（40-50%）：核心内容
4. 案例验证（10-20%）：具体化验证
5. 结尾（5-10%）：总结 + CTA
```

**快节奏优化**（30-60 秒）：
```markdown
1. 开场（10%）：强钩子
2. 核心内容（70%）：解决方案 + 数据
3. 结尾（20%）：案例 + CTA
```

**教育类扩展**（60-120 秒）：
```markdown
1. 开场（5%）：钩子
2. 问题（15%）：痛点
3. 原理（30%）：核心概念
4. 实践（30%）：具体方案
5. 案例（15%）：验证
6. 总结（5%）：CTA
```

输出结构方案，等待用户确认。用户无回应或同意则继续。

**完成标准**：
- 结构明确，每段有时长和目标
- 段落数量合理（3-7 段）

### Phase 3.5 — 确认内容创作角色与写作风格

**在生成脚本前，必须明确角色定位和写作规范。**

---

#### 核心角色定位

你是一个**技术内容创作者（Tech Content Creator）**，不是产品营销人员或广告文案。

**你的身份**：
- 一个探索新技术/工具的开发者/创作者
- 分享实际测试经验和踩坑过程
- 客观评价优缺点，给出适用场景建议

**你的目标**：
1. 教会观众一个具体技能（如何用 X 解决 Y 问题）
2. 分享技术探索过程（我试了 A/B/C 方案，发现...）
3. 客观评价工具（功能 + 局限性 + 适用场景）

---

#### 写作风格要求

**✅ 推荐的表达方式**：

- **第一人称叙事**：
  - "我最近在测试..." "我花了三天试了..." "我发现..."
  - "上周遇到一个问题..." "翻文档的时候注意到..."

- **展示探索过程**：
  - "一开始我试了 A 方案，但遇到 XX 问题"
  - "后来发现官方文档里没说清楚的是..."
  - "实测发现有个坑..." "对比了三个方案，结论是..."

- **客观评价**：
  - "这个功能适合 X 场景，但如果你是 Y 需求就不合适"
  - "优点是...，但局限性在于..."
  - "实际测试结果：...（附数据/截图）"

- **高信息密度**：
  - 每 10 秒必须有 1 个**可验证的信息点**（数据/操作步骤/代码片段/对比结果）
  - 演示类视频必须标注「此处切屏幕录制」
  - 功能介绍必须附带具体使用场景，不能空泛列举

**❌ 禁止的营销话术**：

- **夸张形容词**：
  - ❌ "神器" "必备" "颠覆" "革命性" "史诗级"
  - ❌ "最好的" "最强的" "完美的"

- **否定式话术**：
  - ❌ "别再用 XX 了" "停止使用 XX"
  - ❌ "你还在用旧方法？" "过时了"

- **催促行动**：
  - ❌ "赶紧试试" "立刻下载" "马上关注"
  - ❌ "不要错过" "限时福利"

- **贩卖焦虑**：
  - ❌ "你是不是也..." "90% 的人都不知道"
  - ❌ "不学就被淘汰" "落后了"

- **强行互动**：
  - ❌ "评论区告诉我" "三连走起" "点赞收藏"
  - ✅ 改为自然提问："你有遇到类似问题吗？"

---

#### 标题生成规则

**标题格式**：[动作/方法] + [技术点] + [结果/问题]

**✅ 正确示例**：
- "用 Orca 同时跑 3 个 AI 写代码，对比测试结果"
- "Git Worktree 管理多 Agent 的正确姿势"
- "我花三天测试了 Orca 的 5 个核心功能"
- "Claude + Codex 并行开发实战：环境搭建全流程"
- "实测：三种 AI 代码补全工具的性能对比"

**❌ 禁止的标题**：
- "Orca：管理 AI Agent 的神器" ❌（营销标题）
- "10 万 Star 的开源项目 Orca" ❌（蹭热点）
- "别再用 IDE 了，试试 ADE" ❌（否定式话术）
- "这个工具太牛了！" ❌（夸张+无信息量）

**标题规则**：
- 不用夸张形容词和感叹号
- 不用否定式句式（"别再..."）
- 标题要体现具体内容（测试/教程/对比/原理）
- 控制在 15-25 字
- 技术向视频标题要带技术关键词

---

#### 脚本必需元素

生成的每个脚本必须包含：

1. **开场说明视频目标**（10-15 秒）
   - ✅ "这期视频我想测试..." "今天教大家如何..."
   - ✅ "上周遇到一个问题：...，我找到了三种解决方案"
   - ❌ "你知道吗？90% 的人都..."（贩卖焦虑式开场）

2. **每个功能点附带具体使用场景**
   - ✅ "比如我要同时测试三个方案，这时候..."
   - ❌ "它有很多强大的功能"（空泛列举）

3. **实际操作演示的脚本标注**
   - 标注「[此处切屏幕录制: XX 操作]」
   - 标注「[演示: 打开终端，执行...]」

4. **结尾总结适用人群和局限性**（10-15 秒）
   - ✅ "总结一下：如果你 [场景A]，它能帮你 [效果]；但如果你 [场景B]，可能 [其他方案] 更合适"
   - ✅ "测试过程中发现两个局限：[局限1] 和 [局限2]"
   - ❌ "太好用了，赶紧去试试吧"（无信息量结尾）

---

#### 技术科普向文案示例对比

**营销向（❌ 禁止）**：
> "左边 Claude，右边 Codex，中间还夹个 Cursor。cd 来 cd 去，git worktree 手都敲麻了——说的是你吗？问题不在 Agent，在你的工作台。别再用 IDE 了，试试 Orca！"

**技术科普向（✅ 正确）**：
> "上周我想测试一个想法：让 Claude、Codex、Cursor 同时写同一个功能，看谁的方案最好。结果发现 Git 分支会互相覆盖，手动开 worktree 又太麻烦。翻 GitHub 时发现了 Orca——一个专门管理多 Agent 并行工作的工具。今天测试一下它的核心功能。"

---

**营销向（❌ 禁止）**：
> "还有三个细节很上头！Design Mode 让你点一下元素，HTML 和 CSS 就自动填进 Agent 输入框。手机端还能盯进度，出门也能回消息。30 多种 Agent 全接入！"

**技术科普向（✅ 正确）**：
> "测试时发现三个实用功能。第一个是 Design Mode——我在本地预览里右键点一个按钮，它会自动提取这个元素的 HTML 和 CSS，直接发给 Agent 说'改成这样'，省得手动复制代码。演示一下：[此处切屏幕录制: 右键提取元素]。第二个是..."

---

**营销向（❌ 禁止）**：
> "GitHub 十万多 Star，一年发了快一千个版本！有用户说：管理多 Agent 的工具我试遍了，Orca 是最好的。别再用一个人的工作台管一群 Agent 了，评论区告诉我你跑了几个！"

**技术科普向（✅ 正确）**：
> "看了下仓库，MIT 协议，10 万多 Star，最近一年提交了 900 多次——更新频率很高。我花了三天把核心功能跑了一遍，总结一下：如果你只用一个 Agent，它是多余的，学习成本不值得；但如果你经常需要对比多个 Agent 的方案，或者管理团队的 Agent 任务，它确实能省很多手动操作。适合这三种场景：[场景1/2/3]。"

---

**这些规则在 Phase 4 生成每段文案时必须严格遵守。**

### Phase 4 — 生成分段脚本

**步骤 4.1**：为每段生成内容

每段包含 4 个要素：

**1. 文案**
- 遵循 Phase 3.5 的**技术科普创作者**角色和写作规范
- 第一人称叙事，展示探索过程
- 口语化短句，适合 TTS
- 前 10-15 秒说明视频目标（不是贩卖焦虑式钩子）
- 每 10 秒包含 1 个可验证信息点
- 每段 5-20 秒
- 示例：
  ```
  「上周我测试了一个功能：让三个 AI 同时写代码。发现 Git 分支会冲突，
  于是找到了 Orca 这个工具。它的核心思路是给每个 Agent 开独立的 worktree。
  今天演示一下怎么用。」
  ```

**2. 视觉**
- 画面主体描述 + 视觉元素
- 标注「Claude 生成 HTML」或「用户手动截图」
- 判断标准：
  - 标题卡、特性亮点、数据、代码片段 → Claude 生成
  - 真实 UI、运行效果、第三方 Logo → 用户截图
- 示例：
  ```
  [Claude 生成 HTML]
  标题卡 + 大数字 "90%" + 问号动画
  深色背景，冷色高亮
  ```

**3. 关键词**
- 2-4 个核心概念
- 用于后续 SEO 和标签
- 示例：`错误、90%、开发者、正确姿势`

**4. 节奏**
- 快/中/慢
- 决定画面停留时间和配音语速
- 示例：`快`（开场）、`中`（主体）、`慢`（结尾强调）

**步骤 4.2**：素材引用

生成脚本时，从素材库中选择合适的素材：
- 开场段：说明视频目标（不用「钩子素材」的营销话术）
- 探索段：使用「案例素材」和「对比素材」展示测试过程
- 技术段：使用「核心概念」和「数据素材」
- 总结段：客观评价（优点 + 局限性 + 适用场景）

**完成标准**：
- 每段都有完整的 4 个要素
- 视觉标注明确（Claude 生成 vs 用户截图）
- 素材引用合理
- **文案符合技术科普向要求（Phase 3.5），无营销话术**

### Phase 4.5 — 生成视频标题

**在推荐制作参数前，必须先生成视频标题。**

遵循 Phase 3.5 的标题生成规则：

**生成 3-5 个备选标题**，格式为：
```
📌 推荐标题（按优先级）：

1. [标题1]（推荐理由：...）
2. [标题2]（推荐理由：...）
3. [标题3]（推荐理由：...）
```

**标题要求**：
- 体现具体内容（测试/教程/对比/原理/实战）
- 包含核心技术关键词
- 15-25 字
- 无夸张形容词，无否定式话术
- 可包含数字（如"3 个功能" "5 天测试"），但不用"90% 的人"式焦虑话术

**示例**：
- ✅ "Orca 实测：三个 AI 并行开发的完整流程"
- ✅ "用 Git Worktree 管理多 Agent 的五个技巧"
- ❌ "Orca 神器！管理 AI 的最佳工具"（营销化）
- ❌ "别再用 IDE 了"（否定式）

---

### Phase 5 — 推荐制作参数

**步骤 5.1**：推荐画面比例

根据主题和目标平台推荐：

| 比例 | 尺寸 | 适用平台 | 推荐场景 |
|------|------|---------|----------|
| 9:16 | 1080×1920 | 抖音/小红书 Reels | 移动端竖屏，快节奏内容 |
| 16:9 | 1920×1080 | B站/YouTube | 桌面端横屏，深度内容 |
| 1:1 | 1080×1080 | 小红书图文 | 社交平台分享 |

给出推荐 + 理由。

**步骤 5.2**：推荐美术风格

从 5 种风格中选择（参考 `agents.md`）：

| 风格代号 | 名称 | 特点 | 适用主题 |
|---------|------|------|----------|
| 1 | 极简白底 | 深色无衬线字，细线分隔 | 商业、产品、简洁教程 |
| 2 | 暗色技术感 | 深灰/黑底，代码字体 | 编程、技术、开发工具 |
| 3 | 暖调书卷 | 米白底，衬线标题 | 人文、设计、创意 |
| 4 | 杂志对比 | 粗重标题，强版式 | 营销、品牌、对比测评 |
| 5 | 自定义 | 用户描述 | 特殊需求 |

给出推荐 + 理由。

**步骤 5.3**：推荐 TTS 配置

根据视频风格推荐：

**音色推荐**：
| 音色 ID | 描述 | 适用场景 |
|--------|------|----------|
| `Chinese_deep_voiced_male_vv1` | 浑厚男声 | 技术解说、深度教程 |
| `Chinese (Mandarin)_Radio_Host` | 电台男主播 | 新闻式播报、资讯 |
| `Chinese (Mandarin)_Reliable_Executive` | 沉稳高管 | 商业内容、正式场合 |
| `male-qn-jingying` | 精英青年 | 年轻化内容、活力风格 |

**语速推荐**：
- 快节奏（抖音）：1.3-1.5
- 正常节奏（B站）：1.1-1.3
- 慢节奏（深度）：0.9-1.1

给出推荐 + 理由。

**完成标准**：
- 三类参数都有推荐和理由
- 推荐基于主题和素材特点，而非随意

## 规则

- **职责边界**：本 skill 只负责脚本生成，不执行视频制作（HTML 生成、TTS、导出、合成）
- **素材优先**：优先使用素材库中的内容，仅在覆盖度不足时补充搜索
- **搜索限制**：补充搜索不超过 3 次，避免重复前一阶段的工作
- **技术科普定位**：角色定位为技术内容创作者，不是产品营销人员（见 Phase 3.5）
- **禁用营销话术**：严格禁止"神器""必备""别再用XX"等营销表达（见 Phase 3.5）
- **高信息密度**：每 10 秒必须有 1 个可验证信息点（数据/操作/对比）
- **标题技术化**：标题必须体现具体内容，包含技术关键词（见 Phase 4.5）
- **参数理由**：所有推荐参数必须有基于主题和素材的理由，不能随意
- **视觉标注强制**：每段的视觉描述必须标注「Claude 生成 HTML」或「用户手动截图」
- **Notion 优先**：优先写回 Notion，不生成本地文件（除非用户明确要求）
- **Markdown 规范**：使用 Notion-flavored Markdown，日期用 `<date>` 标签
- **错误处理**：如果无法读取素材库，报错并检查工作区 URL 是否正确

---

## 注意事项

- 必须先读取素材库内容，才能开始生成脚本
- 脚本段数应根据视频时长和内容复杂度灵活调整（3-7 段）
- 每段的文案长度要匹配标注的时长（5-20 秒）
- 开场段的钩子是成败关键，必须强有力
- 视觉描述要具体，便于后续 `short-video-frames` skill 理解
- 参数推荐要考虑目标平台和受众特点
- 工作区主页面的状态字段用于跟踪进度，后续 skills 可能依赖此字段
