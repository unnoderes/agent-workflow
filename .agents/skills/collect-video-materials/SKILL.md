# collect-video-materials

## 职责

为视频制作创建 Notion 工作空间，收集并整理素材到结构化文档。不生成脚本内容。

---

## 工作流

### Phase 1 — 创建 Notion 工作空间

**步骤 1.1**：创建工作区主页面

调用 `notion__notion_create_pages__22d0df52` 创建工作区主页：

```json
{
  "pages": [{
    "properties": {
      "title": "[视频主题] - 视频制作工作区"
    },
    "content": "# [视频主题] - 视频制作工作区\n\n## 📋 项目信息\n- **主题**: [视频主题]\n- **目标时长**: 待定\n- **创建时间**: <date start=\"YYYY-MM-DD\" />\n- **状态**: 🟡 素材收集中\n\n---\n\n## 📚 素材库\n[下方子页面]\n\n## 📝 视频脚本\n[待生成]\n\n---\n\n> 💡 **工作流程**\n> 1. ✅ 素材收集（当前阶段）\n> 2. ⏳ 脚本生成（下一阶段）\n> 3. ⏳ 视频制作",
    "icon": "🎬"
  }],
  "creation_mode": "draft"
}
```

保存返回的 `page_id` 和 `url`（工作区主页面 ID 和 URL）。

**步骤 1.2**：创建素材库子页面

调用 `notion__notion_create_pages__22d0df52` 创建素材库页面：

```json
{
  "pages": [{
    "properties": {
      "title": "📚 素材库"
    },
    "content": "# 📚 素材库\n\n## 🎣 钩子素材（开场吸引点）\n_搜索后填充_\n\n## 📊 数据素材\n_搜索后填充_\n\n## 💡 案例素材\n_搜索后填充_\n\n## 🔄 对比素材\n_搜索后填充_\n\n## 🔗 参考链接\n_搜索后填充_",
    "icon": "📚"
  }],
  "parent": {
    "page_id": "<工作区主页面ID>",
    "type": "page_id"
  }
}
```

保存返回的素材库 `page_id` 和 `url`。

**步骤 1.3**：创建脚本页面（空白占位）

调用 `notion__notion_create_pages__22d0df52` 创建脚本页面：

```json
{
  "pages": [{
    "properties": {
      "title": "📝 视频脚本"
    },
    "content": "# 📝 视频脚本\n\n_此页面将在素材收集完成后，由 generate-video-script 填充内容_\n\n---\n\n等待生成...",
    "icon": "📝"
  }],
  "parent": {
    "page_id": "<工作区主页面ID>",
    "type": "page_id"
  }
}
```

保存返回的脚本页面 `page_id`。

**完成标准**：
- 3 个页面已创建（工作区主页、素材库、脚本占位）
- 所有页面 ID 和 URL 已保存
- 向用户汇报工作区 URL

---

### Phase 2 — 联网搜索素材

**步骤 2.1**：执行 3 轮搜索

使用 `web_search` 依次搜索：

1. **核心信息搜索**（主题关键词 + 2025/最新）
   - 目标：获取技术定义、核心概念、最新动态
   - 记录：可用的钩子（数据、反差、疑问）

2. **案例搜索**（主题关键词 + 案例/实战/应用）
   - 目标：真实使用场景、成功案例、数据对比
   - 记录：可引用的具体场景、效果数据

3. **痛点搜索**（主题关键词 + 问题/误区/对比）
   - 目标：用户常见误解、痛点、竞品对比
   - 记录：可共鸣的痛点、对比维度

**步骤 2.2**：提取结构化信息

从搜索结果中提取：

```markdown
### 钩子素材
- **类型**: 数据型 / 疑问型 / 反差型
- **内容**: [一句话钩子]
- **来源**: [URL]
- **适用场景**: 开场前 5 秒

### 数据素材
- **数值**: XX%
- **描述**: [数据说明]
- **来源**: [URL]
- **可视化建议**: 大数字卡片 / 对比图表

### 案例素材
- **标题**: [案例名称]
- **场景**: [使用场景]
- **效果**: [具体成果]
- **截图需求**: 是/否
- **来源**: [URL]

### 对比素材
- **对比项**: A vs B
- **维度**: [对比维度]
- **结论**: [优劣分析]
- **来源**: [URL]
```

**完成标准**：
- 至少执行 3 次 web_search
- 提取到至少 2 个钩子、3 个数据点、2 个案例、1 个对比
- 所有素材都有来源 URL

---

### Phase 3 — 写入 Notion 素材库

**步骤 3.1**：生成 Notion Markdown 内容

将提取的素材转换为 Notion-flavored Markdown：

```markdown
# 📚 素材库

## 🎣 钩子素材（开场吸引点）

### 钩子 1: [标题]
- **类型**: 数据型
- **内容**: 「[钩子文案]」
- **来源**: [URL]
- **适用场景**: 开场前 5 秒

### 钩子 2: ...

---

## 📊 数据素材

### 数据 1: [描述]
- **数值**: XX%
- **来源**: [URL]
- **可视化建议**: 大数字卡片 + 趋势图

---

## 💡 案例素材

### 案例 1: [标题]
- **场景**: [使用场景]
- **效果**: [具体成果]
- **截图需求**: 是（需真实 UI 截图）
- **来源**: [URL]

---

## 🔄 对比素材

### 对比 1: [A vs B]
- **维度**: [对比维度]
- **结论**: [优劣分析]
- **来源**: [URL]

---

## 🔗 参考链接
- [来源 1 标题](URL1)
- [来源 2 标题](URL2)
- [来源 3 标题](URL3)

---

_素材收集完成时间: <date start="YYYY-MM-DD" />_
```

**步骤 3.2**：更新素材库页面

调用 `notion__notion_update_page__2109c370`：

```json
{
  "page_id": "<素材库页面ID>",
  "command": "replace_content",
  "content": "[上述生成的 Markdown 内容]"
}
```

**步骤 3.3**：更新工作区主页面状态

调用 `notion__notion_update_page__2109c370`：

```json
{
  "page_id": "<工作区主页面ID>",
  "command": "update_content",
  "old_str": "- **状态**: 🟡 素材收集中",
  "new_str": "- **状态**: ✅ 素材收集完成"
}
```

**完成标准**：
- 素材库页面内容已更新
- 工作区主页状态已更新为「素材收集完成」

---

### Phase 4 — 输出汇报

输出以下信息：

```
✅ 素材收集完成！

📦 Notion 工作区: [工作区主页 URL]

📊 收集统计:
  - 钩子素材: X 个
  - 数据素材: X 个
  - 案例素材: X 个
  - 对比素材: X 个
  - 参考链接: X 个

📚 素材库页面: [素材库 URL]

---

🚀 下一步:
运行 `generate-video-script` 并提供工作区 URL，生成视频脚本。

命令示例:
"Generate video script from workspace: [工作区 URL]"
```

**完成标准**：
- 向用户提供工作区 URL 和素材库 URL
- 明确告知下一步操作

---

## 规则

- **职责边界**：本 skill 只负责素材收集，不生成脚本内容、不推荐参数、不设计结构
- **搜索强制**：必须执行至少 3 次 web_search，不能跳过
- **来源追溯**：每个素材必须标注来源 URL
- **Notion 优先**：优先创建 Notion 工作区，不输出本地文件
- **页面结构**：严格按照模板创建 3 个页面（工作区主页 + 素材库 + 脚本占位）
- **Markdown 规范**：使用 Notion-flavored Markdown，日期用 `<date>` 标签，人物用 `<mention>` 标签
- **错误处理**：如果 Notion MCP 不可用，报错并建议用户检查 MCP 连接

---

## 注意事项

- 素材库页面的内容结构（钩子、数据、案例、对比、链接）是固定的，不要省略任何章节
- 即使某类素材暂时为空，也要保留章节标题和 `_待补充_` 占位
- 工作区主页面的状态字段用于跟踪进度，后续 skill 会依赖此字段
- 所有页面默认创建为私有草稿（`creation_mode: "draft"`），用户可自行移动到目标位置
