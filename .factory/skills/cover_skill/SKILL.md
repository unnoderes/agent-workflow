# short-video-cover

## 工作流

### Phase 0 — 信息收集

执行前确认以下输入（未提供的向用户询问）：

- **视频标题**（将成为封面主标题）
- **副标题 / 核心卖点**（一句话，10 字以内最佳）
- **项目关键数据**（可选，如 Stars 数、语言、类型标签）

---

### Phase 1 — 风格与规格确认

**封面比例**
- A · 16:9（1920 × 1080）— B 站横屏封面
- B · 3:4（1080 × 1440）— 小红书封面
- C · 9:16（1080 × 1920）— 抖音竖屏封面

**美术风格**（与 short-video-frames 保持一致）
- 1 · 极简白底
- 2 · 暗色技术感
- 3 · 暖调书卷（#faf8f4 + 金色）
- 4 · 杂志对比
- 5 · 自定义

**可选元素**（多选）
- [ ] 项目 Stars 数字大字展示
- [ ] 编程语言标签
- [ ] "开源推荐" / "本周必看" 等角标徽章
- [ ] 作者头像占位区（留白，用户后期叠加）

等待用户确认后进入 Phase 2。

---

### Phase 2 — 封面 HTML 生成

**输出文件**：`./video-frames/cover.html`

**硬性要求**：
- 固定宽高与所选比例一致
- 完全自包含，外部字体仅用 Google Fonts CDN
- 不使用本地路径 `<img>`
- 文件首行注释：`<!-- Cover | [视频标题摘要] | [风格代号] -->`

**封面设计原则**（Claude 自主执行）**：

封面的核心任务是在缩略图尺寸下（约 320px 宽）仍能清晰传递「这是什么、值不值得点进去」。设计时应当：

- 主标题字号足够大，缩略图下可读（建议不低于画面高度的 8%）
- 视觉重心明确，不超过 3 个信息层级
- 选用能在深色/浅色背景下均清晰的配色对比
- 可用 CSS 几何图形、数字大字、色块分割构建视觉张力
- 如果有 Stars 数字，用超大字号作为视觉锚点——数字本身就是卖点

---

### Phase 3 — 输出说明

生成完毕后输出：

```
已生成：./video-frames/cover.html

在浏览器中打开文件审核样式：
  macOS/Linux：open ./video-frames/cover.html
  Windows：start ./video-frames/cover.html

如需截图导出，运行 /html-image-export 并指定该文件路径。
```

---

## 注意

- 封面与视频帧是不同文件，不合并
- 若已执行 short-video-frames 且风格已确认，封面直接沿用，无需重复选择
- 导出由后续指令执行，本 skill 不自动触发
